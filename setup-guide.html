2

Get Your GHL API Keys

You need a Private Integration API Key and Location ID for each GHL sub-account you want to connect.

  1. Log into your GoHighLevel sub-account
  2. Go to Settings → Business Profile and copy the Location ID (or find it in the URL: app.gohighlevel.com/v2/location/YOUR_LOCATION_ID/...)
  3. Go to Settings → Integrations → Private Integrations
  4. Click Create Private Integration
  5. Name it (e.g., "Claude MCP")
  6. Enable these scopes (at minimum):
    • Contacts (read/write)
    • Conversations/Messages (read/write)
    • Opportunities (read/write)
    • Calendars (read/write)
    • Email Templates (read/write) — labeled as emails/builder.write
    • Locations / Custom Fields (read/write)
    • Any other scopes for features you plan to use
  7. Click Save and copy the API Key (starts with pit-)
⚠
Repeat for each sub-account you want to connect. Each sub-account needs its own Private Integration API key and Location ID.

Clone and Install

Open your terminal and run:

# Clone the repository
git clone https://github.com/mastanley13/GoHighLevel-MCP.git
cd GoHighLevel-MCP

# Install dependencies
npm install

You should see a successful install with no errors. The project structure looks like this:

GoHighLevel-MCP/

Configure Environment

Create a .env file in the project root. Choose the format that fits your setup:

# .env - Single account setup
GHL_API_KEY=pit-your-api-key-here
GHL_LOCATION_ID=your-location-id-here
GHL_BASE_URL=https://services.leadconnectorhq.com
# .env - Multi-account setup
# List your account names (no spaces around commas)
GHL_ACCOUNTS=Acme,BetaCorp,GammaLLC

# Acme credentials
GHL_Acme_API_KEY=pit-xxxxxxxxxxxxx
GHL_Acme_LOCATION_ID=abc123def456

# BetaCorp credentials
GHL_BetaCorp_API_KEY=pit-yyyyyyyyyyyyy
GHL_BetaCorp_LOCATION_ID=ghi789jkl012

# GammaLLC credentials
GHL_GammaLLC_API_KEY=pit-zzzzzzzzzzzzz
GHL_GammaLLC_LOCATION_ID=mno345pqr678

GHL_BASE_URL=https://services.leadconnectorhq.com
ⓘ
The first account in the list (Acme) becomes the active default on startup. Account names can be anything — use client names, project names, etc. No spaces in names.
⚠
Never commit your .env file to Git. It contains secret API keys. The .gitignore should already exclude it.

Build the Server

npm run build

This compiles TypeScript into the dist/ folder. You should see no errors. If you do, make sure you ran npm install first.

To verify the build worked:

ls dist/server.js dist/http-server.js

Connect to Claude Code (CLI)

If you use Claude Code instead of (or in addition to) Claude Desktop, add the server to your Claude Code MCP config:

claude mcp add ghl -- node /full/path/to/GoHighLevel-MCP/dist/server.js

For multi-account, set the environment variables in your shell before running Claude Code, or create a wrapper script:

#!/bin/bash
# save as run-ghl-mcp.sh
export GHL_ACCOUNTS="Acme,BetaCorp"
export GHL_Acme_API_KEY="pit-xxx"
export GHL_Acme_LOCATION_ID="abc123"
export GHL_BetaCorp_API_KEY="pit-yyy"
export GHL_BetaCorp_LOCATION_ID="def456"
export GHL_BASE_URL="https://services.leadconnectorhq.com"
node /full/path/to/GoHighLevel-MCP/dist/server.js

Then register it:

claude mcp add ghl -- bash /full/path/to/run-ghl-mcp.sh

Alternatively, if your .env file is configured, the server will read from it automatically.

Deploy to Railway (Remote Hosting)

Hosting the server on Railway means you manage all accounts in one place — no config files on individual machines. Railway keeps the server always running with instant responses.

ⓘ
Why Railway? This MCP server uses persistent SSE connections that need a long-running Node.js process. Serverless platforms (Cloudflare Workers, Vercel) won't work due to execution time limits. Railway runs your server 24/7 and offers ~$5/month of free compute — enough for this server.

8a. Create a Railway Account

  1. Go to https://railway.app and sign up (GitHub login is easiest)
  2. You'll land on the dashboard — no credit card needed for the free tier

8b. Push Your Code to GitHub

Railway deploys from a GitHub repo. If your code isn't already on GitHub:

# Create a new repo on github.com, then:
cd GoHighLevel-MCP
git remote add origin https://github.com/YOUR_USERNAME/GoHighLevel-MCP.git
git push -u origin main
⚠
Make sure .env is in your .gitignore so your API keys are never pushed to GitHub. Railway has its own secure way to set environment variables.

8c. Create a New Railway Project

  1. On the Railway dashboard, click "New Project"
  2. Select "Deploy from GitHub Repo"
  3. Find and select your GoHighLevel-MCP repository
  4. Railway will detect it as a Node.js project and start deploying

8d. Configure Build & Start Commands

Click on your service in Railway, go to Settings, and set:

SettingValue
Build Commandnpm install && npm run build
Start Commandnpm run start:http

Railway usually auto-detects these, but verify they're correct.

8e. Set Environment Variables

In your Railway service, go to the "Variables" tab and add your GHL credentials. Click "New Variable" for each one:

To add or remove accounts later, just update the variables in Railway's dashboard and the server will automatically redeploy. No code changes needed.

8f. Generate a Public URL

  1. In your Railway service, go to Settings → Networking
  2. Click "Generate Domain"
  3. Railway will give you a URL like: https://ghl-mcp-server-production-xxxx.up.railway.app

Test that it's working by visiting your URL in a browser. You should see a JSON response with the server info.

8g. Verify the Deployment

Check these endpoints to confirm everything is running:

8h. Connect Claude to the Hosted Server

Now update your Claude Desktop config to point to the Railway URL instead of a local server:

{
  "mcpServers": {
    "ghl": {
      "url": "https://your-app.up.railway.app/sse"
    }
  }
}

That's it — no command, args, or env needed. Claude connects to the remote server over SSE. All account credentials live securely on Railway.

  • Add/remove GHL accounts by editing Railway variables — no client updates
  • Server is always running (no cold starts or sleep delays)
  • Auto-deploys when you push code changes to GitHub
  • View logs in real-time from the Railway dashboard
  • Free tier covers typical usage (~$1-3/month)

Multi-Account Usage

When multiple accounts are configured, Claude has two special tools:

ToolWhat It Does
list_subaccountsShows all configured accounts and which is currently active
switch_subaccountSwitches all subsequent calls to a different account

Example conversation:

You:  "What sub-accounts do I have?"
Claude: calls list_subaccounts → shows Acme (active), BetaCorp, GammaLLC

You:  "Switch to BetaCorp and show me their recent contacts"
Claude: calls switch_subaccount(name: "BetaCorp")
       calls search_contacts → returns BetaCorp's contacts

You:  "Now check Acme's email templates"
Claude: calls switch_subaccount(name: "Acme")
       calls get_email_templates → returns Acme's templates

The first account in your GHL_ACCOUNTS list is the default active account when the server starts.

Troubleshooting

Server won't start

  • Check that node --version is 18+
  • Run npm install again
  • Run npm run build and check for errors
  • Verify your .env has no typos in variable names

API calls return 401 Unauthorized

  • Your API key may be invalid or expired — regenerate it in GHL
  • Make sure the key starts with pit- (Private Integration Token)
  • Check that the Location ID matches the sub-account the key was created in

API calls return 403 Forbidden

  • The API key is missing required scopes — go to GHL Settings → Private Integrations and enable the needed permissions
  • Common missing scopes: emails/builder.write, locations/customFields.write

Claude doesn't see the MCP server

  • Make sure you fully restarted Claude Desktop after editing the config
  • Check that the path in "args" points to dist/server.js (not src/server.ts)
  • Make sure the path is absolute, not relative
  • On Windows, use double backslashes: "C:\\Users\\..."

Multi-account: "Account not found"

  • Account names are case-sensitive — Acme is different from acme
  • Make sure the name matches exactly between GHL_ACCOUNTS and GHL_{name}_API_KEY
  • No spaces in account names

View server logs

The server logs to stderr. To see logs when running locally:

# Run stdio server with visible logs
node dist/server.js 2>&1

# HTTP server logs to console automatically
npm run start:http

Railway: deploy fails

  • Check the build logs in Railway → Deployments → click the failed deployment
  • Make sure Build Command is npm install && npm run build
  • Make sure Start Command is npm run start:http
  • Verify all required environment variables are set (no typos in variable names)

Railway: server starts but Claude can't connect

  • Make sure you generated a public domain in Railway → Settings → Networking
  • Your Claude Desktop config should use "url" pointing to https://your-app.up.railway.app/sse (note the /sse path)
  • Visit https://your-app.up.railway.app/health in a browser to confirm the server is reachable
  • Check Railway logs for connection errors

Railway: exceeded free tier

  • Check usage at Project Settings → Usage in Railway
  • The free tier gives $5/month of credit — this server typically uses $1-3/month
  • If you exceed it, add a payment method in Railway to continue service
